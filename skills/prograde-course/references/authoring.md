# 教材の書き方

このファイルは、Prograde のコースを「学習者が手を動かして 1 つずつ理解する」形に組み立てるための指針。データの形は `course-data.md` を見る。

## まずカリキュラムを決める

最初に、コース > レッスン > 章 > セクションの表を作る。セクションが最小の学習単位で、1 つの概念と 1 つの演習を持つ。

| レッスン | 章 | セクション | 演習 ID | 学ぶこと | 学習者が書くこと | 合格条件 |
| --- | --- | --- | --- | --- | --- | --- |

### 粒度

- 1 セクションで新しく学ぶことは 1 つ。`for` と `while` を同じセクションに入れない。
- 演習は 5〜15 分で終わる大きさ。1 行足すだけの演習は、前のセクションの写経になっていないか見直す。
- 章は 2〜4 セクション。レッスンは 2〜5 章。全体コースは 4〜6 レッスンを目安にする。ただし「入門の 1 レッスンだけ」も立派なコース。
- 最初のセクションは、その言語で最も小さい成功体験にする。Python なら `print("Hello")`、Rust なら `println!("Hello")`。
- 各章の最後のセクションは、その章の概念を組み合わせる。新しい概念は入れない。
- コース全体の最後は、白紙から小さなプログラムを書く。ただし 1 ファイルで終わる規模にする。

### 依存関係

セクションの順番は、前のセクションのコードを少し変えれば次が解けるように並べる。次を確認する。

- 使う構文が、それ以前のスライドで説明済みか。
- 前の演習の解答をコピーして、どこを変えるかが明確か。
- 新しい用語を、使う前に説明しているか。

## スライド

スライドは 1 セクションに 2〜4 枚。1 枚 1 メッセージ。

````markdown
# 変数に値を入れる

変数は、値に名前を付けて後から使えるようにするもの。

```python
name = "Taro"
print(name)
```

```text
Taro
```
````

- 先頭は `# 見出し`。スライド一覧のタイトルに使われる。
- 最初の 1 枚で「何ができるようになるか」を 1 文で言う。
- コード例は 5〜10 行まで。実行結果を添える。
- 用語は初出で 1 文の定義を付ける。辞書的な説明を並べない。
- 注意点は最後の 1 枚に置く。例外や落とし穴を最初から並べない。
- 生の HTML はエスケープされる。レイアウトに HTML を使わない。
- 数式は KaTeX。インラインは `$...$`、別行は `$$` で囲む。開始の `$` は行頭・空白・開き括弧の直後、終了の `$` は空白の直前以外に置く。`$x$は` や `$x$、` のように日本語が続いてもよい。コードスパンとコードブロックの中はそのまま表示される。
- 通貨などで `$` を本文に出すときは `\$` とエスケープする。
- 画像は使えるが、必須にしない。画像がなくても本文だけで理解できるようにする。

### 悪いスライド

- 1 枚に概念が 3 つ以上ある。
- コード例が 30 行ある。
- 「〜できます」だけで、実際のコードと出力がない。
- 演習の正解コードをそのまま載せている。

## brief.md

演習の課題文。学習者が最初に読む。次を含める。

1. 何を作るか（1 文）
2. 入力と出力の例
3. 満たすべき条件
4. 使ってよい構文・禁止する構文（必要な場合だけ）
5. 提出するファイル名

````markdown
# あいさつを表示する

`main.py` を編集して、次の 1 行を表示してください。

```text
こんにちは、Taroさん
```

- `print` を 1 回使います。
- 文字列は `"こんにちは、"` と `"さん"` を `+` でつなぎます。
````

- 正解コードを書かない。条件と例で伝える。
- 出力例は、末尾の改行や空白まで判定と一致させる。
- 「〜してください」で終わる短い文にする。長い背景説明を入れない。
- 入力がある演習では、入力の形式と例を必ず書く。

## starter

雛形。学習者が最初に開くファイル。

- 構文として動く状態にする。いきなりコンパイルエラーで始めない。
- 学習者が埋める場所を 1 つか 2 つに絞る。`TODO` コメントを使ってよい。
- 正解に近すぎる雛形にしない。`print("こんにちは、Taroさん")` をそのまま置かない。
- 雛形のまま実行すると、不合格になるようにする。`starterMayPass` は最後の手段。
- 複数ファイルの演習では、編集しないファイルも `files` に含める。`from` で fixtures からコピーする。

## solution

模範解答。`solution/<editable な path>` に置く。

- 最も素直な書き方にする。技巧をひけらかさない。
- 決定論的にする。乱数、現在時刻、ネットワーク、環境依存の値を使わない。
- 雛形と同じファイル構成を保つ。
- コメントは最小限。学習者が読んで理解できる程度。
- 2 回実行して同じ `exitCode` と `stdout` になることを確認する。

## hints

2〜3 段。完成コードではなく、着眼点を書く。

```json
"hints": [
  "文字列は + でつなげます。",
  "print の引数に、つないだ文字列を渡します。"
]
```

- 1 段目は概念の再確認。
- 2 段目は使う構文。
- 3 段目は具体的な式の形。ただしコピペで完成するコードは書かない。
- ヒントが空だと lint の警告になる。

## 判定の設計

判定は「学習者のコードが期待どおり動いたか」だけを見る。書き方の好みを採点しない。

### 基本は exit と stdout

```json
"judge": [
  { "on": "exit", "match": "equals", "value": 0 },
  { "on": "stdout", "match": "exact", "value": "Hello\n" }
]
```

- 終了コード 0 を必ず見る。例外が出ていないことを確認する。
- 出力が 1 行で決まるなら `exact`。末尾改行を含める。
- 出力の一部だけが本質なら `contains`。ただし空文字や短すぎる文字列にしない。
- 数値や JSON を扱うなら `json` と `pointer`。文字列一致より壊れにくい。
- 行数を問うなら `count`。空行は数えない。
- ファイルを作る演習は `exists` と `file`。内容は `contains` か `exact`。

### 緩めすぎない

- `contains` で `"a"` のような 1 文字を見ない。別の出力でも通る。
- `regex` はアンカーを書く。`^` と `$` がないと部分一致で通る。
- `exact` は空白や改行の違いで落ちる。初心者向けの演習では、表示例をそのままコピーできる形にする。
- 複数の正解がある演習では、`exact` をやめて `contains` か `json` にする。

### 判定を分ける

1 つの `judge` に詰め込まず、条件ごとに分ける。`label` を付けると、どこで落ちたかが伝わる。

```json
"judge": [
  { "on": "exit", "match": "equals", "value": 0, "label": "エラーなく終了する" },
  { "on": "stdout", "match": "exact", "value": "合計: 15\n", "label": "合計を表示する" }
]
```

## 環境

`course.json` の `envs` に、その言語の実行環境を書く。

- `probe` は 1 コマンドでバージョンを確認する。`["python3", "--version"]`、`["rustc", "--version"]` など。
- 依存の導入が必要なら `provision` に書く。ただし教材の起動に時間がかかりすぎないようにする。
- `network` は既定 `"off"`。外部 API やパッケージ取得が必要な演習だけ `"on"` にする。
- `limits.timeoutMs` は 100 以上。ビルドに時間がかかる言語は 30000〜60000 を目安にする。
- 環境が足りないときは `remediation` に案内ファイルを置く。

## アンチパターン

- **ソースを grep して採点する。** 実行結果ではなく書き方を採点してしまう。禁止。
- **実行していないのに成功する fixture を使う。** 学習者はコードが動いたと誤解する。禁止。
- **疑似コンパイラでビルドを偽装する。** シェルや言語の教材として不健全。実際の処理系を使う。
- **brief やヒントに完成コードを書く。** 考える余地がなくなる。
- **雛形がそのまま合格する。** 演習にならない。
- **複数の editable ファイルがあるのに `{src}` を使う。** 1 ファイルしか展開されない。`files` を明示するか、コマンドをファイルごとに書く。
- **ネットワークを既定で on にする。** 再現性が落ちる。
- **現在時刻や乱数に依存する出力を exact で判定する。** 決定性がなくなる。
- **Progate などの本文をコピーする。** 説明は自分で書く。構成の参考にとどめる。
- **教材ディレクトリに作業ファイルを置く。** ローダーの検査対象になる。一時ファイルは `/tmp` に置く。

## 仕上げの確認

- 各セクションにスライドが 1 枚以上ある。
- 各セクションに演習がちょうど 1 つある。
- 全演習に `brief.md` と `solution` がある。
- 雛形は不合格、解答は合格する。
- 解答は 2 回実行しても同じ結果になる。
- 判定は実行結果だけを見ている。
- 出力例と判定の空白・改行が一致している。
- ヒントに完成コードがない。
- ネットワークは必要な演習だけ on。
